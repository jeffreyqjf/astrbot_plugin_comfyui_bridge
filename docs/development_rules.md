# 开发规则

[根目录维护指南](../AGENTS.md) 定义职责、工作流发布顺序和已有兼容约束。Architect 负责分派、接口确认和集成。

1. 核对项目与 ComfyUI 工作区、当前分支和运行副本。用只读调查界定业务改动、数据影响和验证范围。若用户尚未批准业务改动，先提交该范围供审批。
2. 为每项派工记录任务目标、角色、可写文件、基线和交付条件。同一文件最多一个写入者。共享接口先达成一致，随后由 Architect 依次安排写入和集成。推理强度按任务实时评估，Low 用于明确的机械核对，Medium 用于局部实现，High 用于复杂交互和跨模块契约，XHigh 用于高风险工作流、迁移或并发问题。发现复杂度变化时重新评估。
3. 有多条独立开发线时，建 `codex/<任务>` 分支和各自 worktree。从记录的基线启动，明确依赖的未提交内容。当前工作区的用户改动属于原工作区，保留其内容。只读任务共用工作区即可。
4. 在批准范围内验证。按改动选择格式检查、单元测试、隔离运行、节点契约检查或桌面与移动交互。执行构建或运行前确认会写入的目录。生成、QQ 投递、生产迁移和安装同步各自记录。
5. Reviewer 对集成差异只读审查，附路径、行号、影响及验证证据。由文件负责人修复，Architect 复核。向用户提供结果、遗留问题和发布影响。提交、推送、发布或清理工作树按授权执行。
6. 每轮结束更新 [开发状态](development_status.md)，并更新本轮实际涉及的架构、工作流、持久数据或 API 文档。涉及用户行为时核对 `user docs/` 下的对应部分。

## 在桌面 App 验证角色

在项目根目录开启新的本地 Codex 会话。项目需处于信任状态。选择只读权限，请主会话使用项目自定义角色 `workflow`、`backend`、`frontend`、`data` 和 `reviewer` 分两批阅读源码。展开子 Agent 活动，检查角色名和各自返回的源码依据。配置规范见 [Codex 子 Agent 文档](https://developers.openai.com/codex/multi-agent)。
