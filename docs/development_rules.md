# 开发规则

[根目录维护指南](../AGENTS.md) 定义单 Agent 开发、工作流发布顺序和已有兼容约束。由当前会话完成以下步骤。

1. 核对项目与 ComfyUI 工作区、当前分支和运行副本。用只读调查界定业务改动、数据影响和验证范围。若用户尚未批准业务改动，先提交该范围供审批。
2. 按依赖拆分任务，记录目标、涉及文件、接口、基线和验收条件。跨模块修改先核对契约，再依序实施。
3. 需要隔离写入时，建 `codex/<任务>` 分支和独立 worktree，并记录基线。保留当前工作区的用户改动。
4. 在批准范围内验证。按改动选择格式检查、单元测试、隔离运行、节点契约检查或桌面与移动交互。执行构建或运行前确认会写入的目录。生成、QQ 投递、生产迁移和安装同步各自记录。
5. 实现后单独检查完整差异，复核接口、数据、工作流和回归风险。修复后复测，报告结果、遗留问题和发布影响。提交、推送、发布或清理工作树按授权执行。
6. 每轮结束更新 [开发状态](development_status.md)，并更新本轮实际涉及的架构、工作流、持久数据或 API 文档。涉及用户行为时核对 `user docs/` 下的对应部分。

项目配置 `.codex/config.toml` 关闭子 Agent。此前的角色定义保留供查阅。
